# ADI Governed Memory Lab: public-launch package

Use these materials only with the public synthetic lab. They do not authorize sharing Cortex, private policies, implementation, records, deployment topology, or any paper under anonymous review.

## Companion dataset

**Proposed repository name:** `BrandenLaskowski7/adi-governed-memory-fixtures`

**Description:** A public, synthetic fixture set for evaluating deterministic memory decisions: temporal eligibility, supersession, conflicts, provenance requirements, scope isolation, replay, and cleanup. Each fixture declares expected decisions; no real people, prompts, documents, sources, or production memory are included.

**Suggested dataset card opening:**

> This dataset contains structured symbolic test fixtures for ADI-inspired governed-memory behavior. It is designed to make failure modes inspectable: a system may correctly return, hold, deny, mark historical, supersede, or leave a query unresolved. The fixtures do not measure truth, general intelligence, model quality, or real-world data governance.

The proposed initial data file is the already public-safe `../fixtures.jsonl` from this release source. Publish it unchanged with a dataset card, license, and a clear statement that receipts are generated by a running lab and are not contained in the fixture file.

## Discussion 1 — launch

**Title:** ADI Governed Memory Lab: deterministic decisions, not a black box

**Body:**

What should happen when a memory is expired, superseded, outside its declared scope, unsupported by provenance, or in conflict with another candidate?

The ADI Governed Memory Lab is a small public, synthetic demonstration of one answer: make the decision deterministic, show the reason category, and preserve a receipt for the operation.

Try the six fixed scenarios here: https://challenge.aiadvantage.shop/demo/

This is not Cortex, a general-purpose memory product, or a security claim. It contains no real records, prompts, private policies, or production infrastructure. It is an invitation to test explicit rules and report a synthetic counterexample.

## Discussion 2 — temporal behavior

**Title:** Memory is not simply retrieved: it has an eligibility window

**Body:**

In the temporal-expiry scenario, the same synthetic record is current one millisecond before expiry, historical exactly at expiry, and absent before its effective time.

That distinction matters because a retrieval system can be technically responsive while still returning information that is no longer eligible for use. The lab makes the transition visible and records each response with a receipt.

Run the synthetic scenario: https://challenge.aiadvantage.shop/demo/

## Discussion 3 — invitation

**Title:** Looking for synthetic counterexamples to governed-memory rules

**Body:**

The lab is designed to be challenged. Pick one invariant—time, scope, provenance, conflict handling, replacement, or cleanup—run the fixed synthetic scenario, and compare the expected decision with the observed response.

If you find a mismatch, report the scenario, expected and observed decision, reason category, receipt ID, and UTC time. Please do not send credentials or real data.

Public reporting path: https://github.com/brandenlaskowski7-bot/cortex-adi-research/issues/new?template=challenge-failure.yml
